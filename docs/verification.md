API-набор проверяет гонки бронирования (20 пар запросов), уникальный индекс, rollback импорта, согласие и валидацию полей, принадлежность записей, все пять ролей, границы данных врача и технической роли, immutable audit, AES-GCM, одноразовость/срок OTP, три ошибки и rate limit, срок/выход сессии, отсутствие PII в открытых полях, сохранение SQLite после перезапуска, outbox lease/retry/opt-out и одноразовую Telegram-привязку с очередью для уже созданной записи.

E2E проходит настоящий путь «услуга → врач → свободный слот → SMS-код → согласие → запись → скачивание .ics». Регистратор видит запись, меняет статус, отменяет изменение и переносит приём. Другой браузер без сессии получает 401. Вторая проверка включает казахский интерфейс, закрытый воскресный день, Escape/возврат фокуса и отсутствие горизонтального переполнения на 320, 360, 390 и 768 px. Проверены изображения страницы, подтверждения и панели на desktop/mobile. Полный ручной аудит WCAG и проверка всех сочетаний браузеров не проводились.

## Нагрузка

Скрипт выполняет каталог и затем DB-backed slots для каждого одновременного посетителя. Измеряется длительность отдельных HTTP-запросов на одном компьютере. После устранения повторного создания Intl.DateTimeFormat:

| БД | Одновременные посетители | HTTP-запросы | Ошибки | p95 |
|---|---:|---:|---:|---:|
| PostgreSQL 18 | 200 | 400 | 0 | 425 мс |
| PostgreSQL 18 | 600 | 1200 | 0 | 926 мс |

Базовая цель p95 < 800 мс при 200 посетителях выполнена в этом локальном прогоне. Утроенный стресс-прогон обслужен без ошибок, но более строгий порог 800 мс на 600 посетителях не выполнен, поэтому скрипт возвращает для него ненулевой exit code. Это не измерение 200 полных OTP/booking операций, SLA или скорости реальной сети. Для сдачи ФЕТ №1/3 требуется согласованный JMeter/k6 сценарий и повтор на целевом стенде.

## Что требует внешнего стенда

- Docker/Compose, Nginx TLS, Grafana и Prometheus добавлены, но контейнерный runtime здесь не был доступен для запуска.
- Реальные SMS/Telegram и SLA провайдеров не проверены: рабочие ключи не предоставлены. Демо ничего не отправляет.
- Размещение в Казахстане, срок хранения, независимый аудит, часовой backup и восстановление RPO/RTO должны быть подтверждены на инфраструктуре клиники.
- Реальный старый журнал отсутствует: импорт проверен на синтетическом CSV/JSON с откатом, но фактические 100% данных не переносились.
- GitHub Actions, gitleaks/Trivy/SBOM добавлены; их удалённые результаты определяются после запуска workflow. Approve, PO acceptance и staging не подменяются локальными тестами.
