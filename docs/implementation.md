# Реализация DentLux

## Какое ТЗ использовано

В репозитории до реализации были документы, но не было приложения. Приоритет отдан согласованному MVP из `docs/lab4/Әселхан_Арлан_Шыңтас_лабка4.docx`, повторённому в lab5 и lab7. README и GitHub Issues описывают более широкий продукт и местами противоречат этим границам.

В MVP входят филиал, каталог и цены, врачи, запись на 30-минутный слот, подтверждение телефона, отдельное согласие на уведомления, подтверждение/напоминание и рабочее место регистратора. Услуги с большим фактическим временем лечения обозначены как первичный приём: дальнейшее лечение планирует клиника. Адрес взят из ТЗ; телефон, реальные врачи, фотографии и утверждённый прайс не предоставлены. Данные специалистов и цены в приложении синтетические.

Не входят в этот релиз: личный кабинет с медицинской историей, самостоятельная отмена/перенос пациентом, платежи, рентген/файлы, бонусы, AI и мобильное приложение. Регистратор может перенести и отменить запись. Эти границы не позволяют считать все десять существующих Issues закрытыми.

## Роли

| Роль | Доступ |
|---|---|
| patient | Создать запись, прочитать своё подтверждение по ID, управлять согласиями на уведомления и Telegram |
| receptionist | Все записи по дате, статусы, перенос, расписание, статистика и очередь уведомлений |
| doctor | Только приёмы, назначенные этому врачу; без изменения чужих расписаний |
| lawyer | Обезличенный журнал аудита |
| admin | Технический статус, обезличенный аудит, состояние уведомлений; без имени/телефона пациентов |

Публичная авторизация не принимает роль. Работников добавляют через STAFF_ACCOUNTS при первом запуске; существующий номер не повышается в правах этим механизмом. Для изменения/отзыва роли нужен контролируемый запрос к БД и удаление сессий этого пользователя. Демо-аккаунты создаются только в development/demo.

## Транзакции и данные

PostgreSQL — серверная БД. Перед записью/переносом/изменением расписания блокируется строка врача `SELECT ... FOR UPDATE`. Частичный уникальный индекс `(doctor_id,date,time)` защищает все статусы, кроме cancelled. Операции записи, аудита и outbox входят в одну транзакцию. SQLite для разработки сериализует транзакции и чтения и использует тот же индекс. Часовой пояс клиники — UTC+5, все внутренние timestamps — UTC.

Ключ AES и AUTH_PEPPER не хранятся в БД. В демо ключ генерируется в игнорируемой `.data/development.key`; это лишь удобство локальной разработки. Имя и телефон зашифрованы и в users, и в bookings. Диагнозы и медицинские файлы система не собирает. Сессии и коды хранятся в виде HMAC. Аудит содержит идентификаторы и изменения расписания, но не контактные поля. DB-триггеры фиксируют изменения основных таблиц без копирования строк с персональными данными; технические таблицы OTP/сессий не копируются в долгоживущий журнал.

Запрет изменения аудита защищает от обычных UPDATE/DELETE. Владелец БД способен снять триггеры, поэтому для требований к независимому неизменяемому архиву нужен отдельный WORM-архив и отдельные учётные данные. Автоматического удаления аудита нет: срок не менее 3 лет из ТЗ обеспечивается политикой хранения, объёмом диска и резервным архивом на целевой инфраструктуре.

## Уведомления

Без реальных ключей включён только явно помеченный демо-режим: код показывается в интерфейсе, очередь получает статус demo, реальные сообщения не отправляются. Production запрещает этот режим, SQLite, пустые секреты и HTTP origin. SMS адаптер ожидает JSON `{to,text,idempotencyKey}` и Bearer token. Под контракт конкретного оператора его нужно адаптировать в `backend/notifications.mjs`; HTTP 2xx означает приём шлюзом, а не гарантированную доставку на устройство.

Напоминания создаются только при opt-in и не создаются, если до приёма меньше двух часов. Отправка имеет семантику at-least-once: провайдер обязан поддержать Idempotency-Key, иначе после аварии процесса возможен повтор. Outbox использует атомарный захват и lease; неуспех после трёх попыток виден в панели и аудите. Перенос отменяет старую очередь и создаёт новую версию уведомлений. Уже начатая внешняя отправка не может быть отозвана. SMS OTP не повторяется автоматически, чтобы не отправлять несколько кодов; можно запросить заново в пределах лимита.

Telegram подключается одноразовой ссылкой, созданной в подтверждённой SMS-сессии, на 5 минут; бот принимает её только из приватного чата. При подключении после бронирования бот поставит в очередь подтверждение и будущие напоминания для уже созданных активных записей с opt-in. В сообщения не включаются имя, телефон, врач или услуга. Убедитесь, что бот не обслуживается другим long-polling/webhook приложением.

## Ограничения измерений

Нагрузочный скрипт моделирует параллельный просмотр каталога и реальных слотов БД; он не доказывает SLA, производительность сети клиники или 600 одновременных авторизаций. SMTP/email и банковский эквайринг намеренно не интегрированы. Прометей создаёт алерты, но доставку инженеру надо подключить через Alertmanager/контактные точки Grafana. Почасовой backup даёт целевой RPO 1 час при исправной инфраструктуре; RTO 4 часа нужно подтвердить восстановлением и замером на сервере. Работа Docker Compose и внешних каналов локально не заявляется проверенной.
