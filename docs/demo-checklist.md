# DentLux перед демонстрацией

## Что показать

1. Запустить `npm ci`, затем `npm run dev`. Открыть `http://127.0.0.1:5173`.
2. Выбрать услугу, врача и время. Ввести тестовый номер, подтвердить код с экрана, записаться и скачать календарь.
3. Войти как регистратор через кнопку «Сотрудникам». Открыть день записи, поменять статус, отменить изменение и перенести приём.
4. После загрузки дня временно отключить запрос расписания и нажать «Обновить». Сохранённое расписание показывает время, врача и статус. После восстановления запроса кнопка «Обновить» возвращает полный список.
5. Запустить `npm test` и `npm run test:e2e` после `npm run build`. Проверки включают конфликт записи, импорт 100 строк, восстановление копии SQLite, сбой отправки уведомления, содержимое файла календаря и просмотр расписания при недоступном запросе.

Сохранённое расписание доступно в той же вкладке после проверки входа, даже если запрос записей временно не работает. Данные относятся к выбранной дате. Имя, телефон и номер записи в снимок не входят.

Для показа настоящей доставки [подключите Telegram](operations.md#настоящие-уведомления-в-telegram), создайте учебную запись с согласием на уведомления и откройте одноразовую ссылку. На защите покажите полученное сообщение в личном чате бота.

## Что нужно от команды

| Лаба | Материал или участие |
| --- | --- |
| №6 | Выгрузка завершённых карточек с ID, датой завершения и Story Points по неделям. Для сравнения двух способов оценки выбрать один и тот же набор историй. Допустим набор данных, выданный для задания |
| №9 | [В GitHub найдено 42 перехода](assets/lab9-github-status-events.csv), все 29 октября. Для двух спринтов нужны переходы с ID, статусом и временем. Подойдёт выгрузка из другого трекера, где велась эта работа. Для нового прогона фиксировать смену статусов по мере работы. Провести ретроспективу и записать одно решение, ответственного и срок |
| №11 | Другая команда проходит 12 сценариев на демо. В протокол записать фактический результат каждого сценария, дату и подписи. В сценарии календаря импортировать скачанный файл и сверить время |
| №12 | Исходная папка «Дополнения» или её архив с кодом эксперимента, входными файлами и журналом ответов. В `raw-results.json` нужны ответ, задержка и количество токенов для каждого из 40 примеров |

Для работы в проекте можно использовать эту сверку, чтобы заполнить поля карточек по CSV и переносить карточки по результатам проверки. Для №10 отчёт DORA появится в артефактах GitHub Actions после запуска на основной ветке. Метрики с недостаточными данными сохраняются как `N/A`. Протокол №11 находится в [лабе №11](lab11.md#22-қабылдау-хаттамасы).
